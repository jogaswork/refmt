# MT Team — Telegram-бот приёма заявок

Бот на **aiogram 3.x** с базой данных **SQLite** (через `aiosqlite`, без внешнего сервера БД —
работает "из коробки").

## Возможности

- `/start` (в т.ч. с реферальным payload `/start <user_id>`) — регистрация пользователя.
- Подача заявки через FSM: три вопроса одним сообщением → заявка уходит всем админам.
- Реферальная система: постоянная кнопка «🔗 Реферальная система» в главном меню.
- Админ-панель `/admin`:
  - 📋 Нерассмотренные заявки — принять / отклонить (с указанием причины или без).
  - 🔗 Настройка группы — смена ссылки, которая выдаётся принятым пользователям.
  - 📢 Рассылка — текст/фото/видео/документ всем пользователям бота.
  - 👥 Пользователи (Рефералы) — кто кого пригласил.

## Установка

```bash
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

1. Скопируйте `.env.example` в `.env`:
   ```bash
   cp .env.example .env
   ```
2. Заполните `.env`:
   ```
   BOT_TOKEN=токен_от_BotFather
   ADMIN_IDS=111111111,222222222
   GROUP_LINK=https://t.me/+ваша_ссылка
   ```

## Запуск

```bash
python bot.py
```

При первом запуске автоматически создастся файл `bot.db` (SQLite) со всеми нужными таблицами.

## Структура проекта

```
mt_team_bot/
├── bot.py              # точка входа, запуск polling
├── config.py            # загрузка .env
├── database.py           # весь доступ к БД (aiosqlite)
├── keyboards.py           # inline / reply клавиатуры
├── states.py             # FSM-состояния
├── handlers/
│   ├── user.py           # /start, анкета, реферальная система
│   └── admin.py           # /admin, заявки, рассылка, настройка группы
├── requirements.txt
└── .env.example
```

## Заметки по эксплуатации

- Заявка считается «pending», пока админ не примет/отклонит её — повторный клик
  по уже обработанной заявке безопасно блокируется (алерт «уже обработана»).
- Рассылка использует `message.copy_to()`, поэтому поддерживает любой тип контента
  (текст, фото, видео, документ, голосовое и т.д.) без дополнительного кода.
- Если пользователь заблокировал бота, ошибки отправки отлавливаются и не роняют бота.
- Для продакшена рекомендуется заменить `MemoryStorage` на `RedisStorage`, чтобы
  состояния FSM переживали перезапуск бота.
